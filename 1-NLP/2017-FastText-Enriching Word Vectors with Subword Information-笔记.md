## FQA



#### Q：受分布式假设 [18] 启发，词表示被训练来预测在其上下文中出现的词。

这句话描述的是 **Word2Vec 类模型**（如 CBOW 和 Skip-gram）的核心训练思想。

分布式假设 (Distributional Hypothesis)

> **"一个词的意义由它周围的词决定"** —— Harris, 1954

即：**语义相似的词倾向于出现在相似的上下文中**。例如：

```
"我 喜欢 吃 [苹果]"
"我 喜欢 吃 [香蕉]"
```

"苹果"和"香蕉"出现在相似上下文中 → 它们语义相近。



训练方式：预测上下文中的词

模型学习一个词向量 $v_w$，使得给定中心词时能预测周围的词：



**Skip-gram（预测上下文）：**

$$P(w_{context} | w_{center}) = \frac{\exp(v'_{w_{context}} \cdot v_{w_{center}})}{\sum \exp(v'_w \cdot v_{w_{center}})}$$



**CBOW（用上下文预测中心词）：**

$$P(w_{center} | w_{context}) = \frac{\exp(v'_{w_{center}} \cdot \bar{v}_{context})}{\sum \exp(v'_w \cdot \bar{v}_{context})}$$



通俗理解

| 概念               | 含义                            |
| ------------------ | ------------------------------- |
| 分布式假设         | 词的意义由其上下文决定          |
| 词表示被训练来预测 | 优化目标是让模型能准确预测      |
| 上下文中出现的词   | 周围窗口内的词（如前后各5个词） |

**本质**：通过"猜上下文"这个简单任务，迫使模型**把语义相似的词映射到相近的向量位置**，从而自动学出有意义的词表示。





#### Q：这段话是什么含义？

**为了限制模型的内存需求，我们使用一个哈希函数将 $n$-gram 映射到 1 到 $K$ 的整数**。我们使用 Fowler-Noll-Vo 哈希函数（特别是 FNV-1a 变体）**对字符序列进行哈希**。我们在下文中设置 $K = 2 \cdot 10^6$。最终，**一个词由其在词典中的索引 和 它包含的哈希 $n$-gram 集合来表示。**



这段话是 FastText 子词机制的核心，我拆开讲：



背景：FastText 用"字符 n-gram"补充词本身

FastText 里每个词不只有词典里一个向量，而是由**它包含的所有字符 n-gram** 共同表示。例如词 `where`（n=3，`<` `>` 是词边界符）：

```
<wh, whe, her, ere, re>
```

**词向量 = 词典向量 + 所有子词向量的和**。



问题：n-gram 种类太多，内存爆炸

- 词典有 ~几百万词
- 每个词有 ~几十个 n-gram
- 所有可能的 n-gram 种类数：**几亿甚至更多**

如果给每个 n-gram 都分配一个独立向量（每个向量几百维浮点数），内存直接爆掉。这就是第一句"**为了限制模型的内存需求**"的原因。



解决：哈希函数把 n-gram 压进固定大小的空间

**哈希（hash）** 的作用：把任意长度的字符串（如 `whe`）变成一个固定范围内的整数。

```
hash("whe") → 一个 1 到 K 之间的整数
```

设置 $K = 2 \times 10^6$（200 万），意味着**最多只维护 200 万个 n-gram 向量槽位**，内存固定可控。多个不同 n-gram 可能哈希到同一个整数（哈希冲突）——实践中影响很小，是"用一点点精度换内存"的标准工程权衡。

**FNV-1a** 是具体用的哈希算法（Fowler–Noll–Vo 的 1a 变体）：一个极快、设计用于字符串哈希的算法，流程是——

```
初始偏移量 → 对每个字符字节：hash ^= byte; hash *= 素数
```

速度极快（几行代码），分布均匀，正适合这种"每秒要哈希几百万个 n-gram"的场景。



最终表示：词典索引 + 哈希 n-gram 集合

一个词由两部分表示：

| 部分 | 内容 | 作用 |
|---|---|---|
| **词典索引** | 词本身在词典中的位置 | 取词本身的向量 $v_{word}$ |
| **哈希 n-gram 集合** | 该词的每个 n-gram 哈希成整数 | 每个整数对应子词向量矩阵中的一行 |

**具体流程（以 `where` 为例，假设 n=3）**：

```
"where" 的 n-gram:  <wh, whe, her, ere, re>
      │ FNV-1a 哈希
      ▼
   整数:  482913, 157023, 899134, 330287, 771210   （1 ~ 200万之间）
      │ 查表（200万 × d 的矩阵）
      ▼
词向量 = v_where + v_482913 + v_157023 + v_899134 + v_330287 + v_771210
```



这样做最大的好处：OOV（词典外）词也能有向量

以前遇到训练时没见过的词（如 `wherever`），只能随机初始化或干脆放弃。现在：

```
"wherever" 从未在词典中出现
  但它的 n-gram: <wh, whe, ... ver, er> 大概率在训练时见过
      ▼
  哈希后取子词向量求和 → 照样得到有意义的向量！
```

**这是 FastText 处理罕见词、拼写变体、形态派生词（whereever、wherever...）的核心机制**——词的语义信息被分散存储在字符片段里，词本身是否在词典中已经不那么重要。



一句话总结

> 因为 n-gram 太多了存不下，就先用 FNV-1a 哈希把每个 n-gram 字符串"折叠"成 1~200 万的整数，用一张固定大小的表存子词向量；最终每个词 = 词典向量 + 它所有哈希 n-gram 向量之和。这样内存可控，还能让没见过的新词靠字符片段拼出向量。
