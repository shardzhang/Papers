安装

• Linux：按照第 1.1 节中的说明编译 libFM。

• MacOS X：按照第 1.1 节中的说明编译 libFM。

• Windows：从 http://www.libfm.org/libfm-1.40.windows.zip 下载编译好的可执行文件。
  您可以跳过第 1.1 节。请注意，编译好的可执行文件的版本是 libFM
  1.4.0。该版本具有与 libFM 1.4.2 相同的功能，但其许可证不同。

1.1 编译

libFM 已在 GNU 编译器套件和 GNU make 下测试通过。这两者通常应已安装在
Linux 和 MacOS X 中。

通过以下步骤，您可以构建 libFM：

1. 下载 libFM 源代码：http://www.libfm.org/libfm-1.42.src.tar.gz

2. 解压和解包：例如 tar -xzvf libfm-1.42.src.tar.gz

3. 进入目录 libfm-1.42.src 并编译工具：make all

文件概览

• license.txt：libFM 的使用许可

• history.txt：版本历史和变更

• readme.pdf：本手册

• Makefile：使用 make 编译可执行文件

• bin：包含可执行文件的文件夹1

  – libFM：libFM 工具
  – convert：用于将文本文件转换为二进制格式的工具

  – transpose：用于转置二进制设计矩阵的工具

• scripts

  – triple_format_to_libfm.pl：一个 Perl 脚本，用于将逗号/制表符分隔的数据集转换为
    libFM 格式。

2 数据格式

libFM 支持两种输入数据文件格式：文本格式和二进制格式。使用
文本格式更简单，推荐给新的 libFM 用户。

2.1 文本格式

数据格式与 SVMlite [3] 和 LIBSVM [1] 相同2：每一行包含一个训练样本
(x, y)，其中 x 是实值特征向量，y 是目标值。该行首先列出 y 值，然后列出
x 的非零值。对于二分类，y > 0 的样本被视为正类，
y \leq 0 的样本被视为负类。

示例

4 0:1.5 3:-7.9
2 1:1e-5 3:2
-1 6:1
...

该文件包含三个样本。第一列指出三个样本中每一个的目标值：即第一个样本为
4，第二个为 2，第三个为 -1。在目标值之后，每行包含 x 的非零元素，
其中像 0:1.5 这样的条目表示 x0 = 1.5，3:-7.9 表示 x3 = −7.9，等等。也就是说，
INDEX:VALUE 的左侧表示 x 中的索引，而右侧表示 xINDEX 的值，即
xINDEX = VALUE。

2.1.1 转换推荐系统文件

在推荐系统中，通常使用类似 userid itemid rating 的文件格式。一个用于将
此类数据集（以及更复杂的，例如上下文感知设置中的数据集）转换为 libFM 文件格式的 Perl 脚本
包含在 scripts 目录中。例如，要将来自 Movielens 1M3 数据集的 ratings.dat 文件
转换为 libFM 格式，调用：

./triple_format_to_libfm.pl -in ratings.dat -target 2 -delete_column 3 -separator "::"

输出将写入一个扩展名为 .libfm 的文件。
在该示例中，输出写入到
ratings.dat.libfm。

如果单个数据集由多个文件组成，例如训练集和测试集划分，则应
同时使用这两个文件调用转换脚本（-in 选项的多个文件）：

./triple_format_to_libfm.pl -in train.txt,test.txt -target 2 -separator "\t"

警告：如果您分别对每个文件运行转换脚本，变量（id）将不会
匹配。例如，第一个文件中的第 n 个变量与第二个文件中的第 n 个变量不同。

2.2 二进制格式*

除了标准文本格式之外，libFM 还支持二进制数据格式。二进制
格式的优点有：(1) 读取更快，(2) 如果您的数据无法放入主内存，二进制数据格式
支持将数据缓存到硬盘上，仅将一小部分保留在内存中（在 libFM 中使用 --cache_size），
(3) 如果您使用 ALS 和 MCMC，可以预计算转置后的设计矩阵，
这在读取数据集时节省时间。

要将 libFM 文本格式的文件转换为二进制数据格式，请使用 bin 文件夹中的工具

3.1 必选参数

• 第一个需要指定的必选参数是 -task，它可以是分类（-task c）或
  回归（-task r）。

• 其次，必须提供训练数据（-train）和测试数据（-test）。您可以在此处使用
  libFM 文本格式或二进制格式的数据文件（关于使用二进制文件的详细信息，参见第 3.2.2 节）。

• 第三，必须使用 -dim 指定因子分解机的维度。该参数
  由三个数字组成：k0, k1, k2。

  – k0 \in {0, 1} 决定是否在模型中使用全局偏置项 w0（详细信息参见 [4]）。

  – k1 \in {0, 1} 决定是否在模型中使用一阶交互（每个变量的偏置项），即 w
    （详细信息参见 [4]）。

  – k2 \in N0 给出用于成对交互的因子数量，即
    V \in Rp×k（详细信息参见 [4]）。

示例 一个用于回归任务的 FM，使用偏置、一阶交互和 k = 8 的因子化用于
成对交互：

./libFM -task r -train ml1m-train.libfm -test ml1m-test.libfm -dim '1,1,8'

3.2 可选参数

3.2.1 基本参数

• out：训练完成后，您可以将测试数据集的所有预测写入由 out 指定的文件。
  out 文件为文本格式，行数与测试数据集相同，第 i 行表示
  第 i 个测试样本的预测值。请注意，对于分类任务，输出的是该样本属于
  正类的概率。

• rlog：生成一个包含每次迭代统计信息的日志文件。该文件为 CSV 格式，使用
  制表符分隔的字段。请注意，报告哪些字段取决于学习方法。

• verbosity：使用参数 -verbosity 1，libFM 会打印更多信息。这对于
  检查数据是否正确读取以及查找错误非常有用。

3.2.2 高级参数*

分组 您可以使用 meta 选项对输入变量进行分组。分组可用于 MCMC、
SGDA 和 ALS，以定义更复杂的正则化结构。每个组可以有一个单独的正则化参数。要使用分组，meta 参数需要一个文本文件名，该文件的行数与
输入变量（设计矩阵的列）的数量相同。每行指定对应输入变量的组 ID。
请注意，组的 ID 应为数字格式，并从 0 开始。例如，用于方程 (1) 示例中的设计矩阵（有 7 列；最大 ID 为 6）的分组文件可以是：

2
2
0
1
1
1
0

这意味着：总共有三个组。前两个变量（设计矩阵中的列）
属于同一组，第三个和最后一个变量属于同一组，第四到第六个变量属于
同一组。

二进制数据和缓存 在第 2.2 节中已说明，二进制文件的文件名应以
.x 结尾表示设计矩阵，以 .y 结尾表示目标值，以 .xt 结尾表示转置数据。如果您想在
libFM 中使用二进制数据，训练、测试和验证的命令行参数的文件名应
指定时不带 .x、.y、.xt 结尾。
即，如果您已准备好训练数据 (ml1m-train.x, ml1m-train.y,
ml1m-train.xt) 和测试数据 (ml1m-test.x, ml1m-test.y, ml1m-test.xt)，调用：

./libFM -task r -train ml1m-train -test ml1m-test -dim '1,1,8'

libFM 将自动附加适当的文件扩展名并加载学习算法所需的
数据文件。

如果您的数据无法放入内存，您可以指定 libFM 允许将多少文件保留
在内存中：

./libFM -task r -train ml1m-train -test ml1m-test -dim '1,1,8' -cache_size 100000000

在此示例中，100,000,000 字节（100 MB）将用作每个 .x 或 .xt 文件的缓存。请注意，
.y 文件始终被完整读入内存。

如果未指定 cache_size 参数，则所有数据都将加载到内存中。注意：仅当数据无法
放入内存时才应使用缓存，因为缓存使用硬盘，这将比内存访问慢得多。

3.3 学习方法

默认情况下，使用 MCMC 推理进行学习，因为 MCMC 是最容易处理的（无需
学习率，无需正则化）。在 libFM 中，您可以从以下学习方法中选择：SGD、
ALS、MCMC 和 SGDA。对于所有学习方法，都必须指定迭代次数 iter。

3.3.1 随机梯度下降 (SGD)

使用 -method sgd 通过 SGD [4] 进行参数学习。对于随机梯度下降，需要
选择以下参数：

• -learn_rate：学习率，即 SGD 的步长，应为非零正值。

• -regular：正则化参数，应为零或正值。对于 SGD，您
  可以通过以下方式指定正则化值：

  – 一个值（-regular value）：所有模型参数使用相同的正则化值。

  – 三个值（-regular 'value0,value1,value2'）：零阶交互 (w0) 使用 value0 作为
    正则化，一阶交互 (w) 使用 value1，成对交互 (V) 使用 value2。

  – 无值：如果完全未指定参数 -regular，则相当于无正则化，
    即 -regular 0。

• -init_stdev：用于初始化参数 V 的正态分布的标准差。
  此处应使用非零正值。

请谨慎选择这些参数，因为预测质量在很大程度上取决于良好的选择。

示例

./libFM -task r -train ml1m-train.libfm -test ml1m-test.libfm -dim '1,1,8' -iter 1000
-method sgd -learn_rate 0.01 -regular '0,0,0.01' -init_stdev 0.1

3.3.2 交替最小二乘法 (ALS)

使用 -method als 通过 ALS [8] 进行参数学习。需要选择以下参数：

• -regular：正则化参数，应为零或正值。对于 ALS，您
  可以通过以下方式指定正则化值：

  – 一个值（-regular value）：所有模型参数使用相同的正则化值。

  – 三个值（-regular 'value0,value1,value2'）：零阶交互 (w0) 使用 value0 作为
    正则化，一阶交互 (w) 使用 value1，成对交互 (V) 使用 value2。

  – 组特定值（-regular 'value0,value1g1,...,value1gm,value2g1,...,value2gm'），
    对于 m 个组，有 1 + 2 * m 个正则化值：
    也就是说，如果输入变量被
    分组，则每个组以及一阶和二阶交互可以使用单独的正则化值。

  – 无值：如果完全未指定参数 -regular，则相当于无正则化，
    即 -regular 0。

• -init_stdev：用于初始化参数 V 的正态分布的标准差。
  此处应使用非零正值。

请谨慎选择这些参数，因为预测质量在很大程度上取决于良好的选择。

示例

./libFM -task r -train ml1m-train.libfm -test ml1m-test.libfm -dim '1,1,8' -iter 1000
-method als -regular '0,0,10' -init_stdev 0.1

3.3.3 马尔可夫链蒙特卡洛 (MCMC)

使用 -method mcmc 通过 MCMC [2] 进行参数学习。需要选择以下参数：

• -init_stdev：用于初始化参数 V 的正态分布的标准差。
  此处应使用非零正值。

请谨慎选择此参数，因为收敛速度取决于良好的选择。

示例

./libFM -task r -train ml1m-train.libfm -test ml1m-test.libfm -dim '1,1,8' -iter 1000
-method mcmc -init_stdev 0.1

3.3.4 自适应 SGD (SGDA)

使用 -method sgda 通过自适应 SGD [6] 进行参数学习。使用自适应 SGD，正则化
值（按组和层级）会自动确定。您必须指定一个验证集，用于
调节正则化值：

• -validation：一个包含训练样本的数据集，用作验证集以调节正则化值。
  该数据集应与训练数据集不同。

• -learn_rate：学习率，即 SGD 的步长，应为非零正值。

• -init_stdev：用于初始化参数 V 的正态分布的标准差。
  此处应使用非零正值。

请谨慎选择这些参数，因为预测质量在很大程度上取决于良好的选择。

示例

./libFM -task r -train ml1m-train.libfm -test ml1m-test.libfm -dim '1,1,8' -iter 1000
-method sgda -learn_rate 0.01 -init_stdev 0.1 -validation ml1m-val.libfm

4 块结构 (BS) 扩展*

图 1：
(a) LibFM 数据文件（= 设计矩阵 X 的表示）可能包含重复模式的大块。
(b) libFM 的 BS 扩展允许使用更紧凑的数据文件表示，
其中重复模式仅描述一次。（图片改编自 [7]）

在关系型设置中，设计矩阵可能包含重复模式的大块（见图 1a）。
这可能导致非常大的设计矩阵，使得学习速度变慢且消耗大量内存。
libFM 的 BS 扩展允许定义和利用设计矩阵中的块结构。
运行时和内存消耗将与 BS 数据大小呈线性关系，而不是原始数据大小。关于
来自关系数据的大型设计矩阵的详细信息，请参见 [7]。

4.1 数据格式

BS 扩展允许定义块（例如图 1 中的 B1, B2, B3）并在 libFM 中使用它们。每个
块定义包括：

• 块的设计矩阵（libFM 文件）（例如图 1 中的 X_B1）。

• 从训练（或测试）样本到块中行的映射（例如图 1 中的 \phiB1）。

• 设计矩阵中变量的可选分组（比较第 3.2.2 节）。

对于每个块，需要以下文件：

文件名               描述
<blockname>.x        块的设计矩阵，二进制格式（例如图 1 中的 X_B1）。
                     可以使用 convert 工具从 libFM 文本格式的文件生成此文件
                     （参见第 3.2.2 节）。
<blockname>.xt       <blockname>.x 的转置，二进制格式。可以使用 transpose 工具
                     从 <blockname>.x 生成此文件（参见第 3.2.2 节）。
<blockname>.train    从训练行到块行的映射（例如图 1 中的 \phiB1）。预期
                     文件为文本格式，行数与训练数据集（在 --train 参数中）相同。
                     在每一行中，文件指出此训练样本链接到 X_B1 中行的索引4。
                     例如，如果第 5 行的条目是 21，则第 5 个训练样本使用 X_B1 的第 22 行的数据。
<blockname>.test     与 <blockname>.train 相同，但此时测试数据集中的行被
                     链接到 X_B1。
<blockname>.groups   预测变量分组的可选文件。格式与第 3.2.2 节中的格式相同。

4.2 使用 BS 数据运行 libFM

块通过命令行参数 --relation 传递。假设已经定义了两个块（rel.user 和
rel.item），调用方式为：

./libFM -task r -train ml1m-train -test ml1m-test -dim '1,1,8' --relation rel.user,rel.item

请注意，对于每个块，上述列出的文件必须存在（即 rel.user.x, rel.user.xt,
rel.user.train, rel.user.test, (rel.user.groups), rel.item.x, rel.item.xt, 等）。

4.3 关于在 libFM 中使用 BS 的说明

• BS 仅受 MCMC 和 ALS/CD 支持。

• 即使在使用 BS 时，--train 和 --test 参数仍然是必选的，并且必须在此处指定文件。
  在 --train 和 --test 中传递的 libFM 文件也可以包含预测变量，
  但也可以为空5。文件可以是二进制或文本格式。

• BS 设计矩阵中变量 id 的命名空间是独立的。例如，一个索引为 7 的变量
  在 X_B1 中、在 X_B2 中以及主训练/测试文件 X 中，各自被视为不同的变量。在内部，
  libFM 将前一个块 X_Bi-1 的最大变量 id 的偏移量加到块 X_Bi 中的每个 id 上。
  因此，建议所有块都从变量 id 0 开始索引，以避免浪费
  内存。

• BS 文件中组的命名空间是独立的。每个组文件可以有从 0 开始的组，
  重叠以与预测变量 id 相同的方式解决。

• 如果没有传递组文件，则自动假定每个块具有不同的组。

4所有索引均从 0 开始。即，第一行的索引是 0，第二行的索引是 1，以此类推。
5目标值仍需指定。预测变量可以为空。
