## FQA

#### Q1：解释下文

通常有价值的特征在必须做出预测时才变得可用。这些特征不能用作输入，因为它们在运行时将不可用。然而，如果学习是离线完成的，它们可以为训练集收集并用作额外的 MTL 任务。学习器对这些**额外任务的预测在系统使用时可能会被忽略**；它们的**主要功能是在训练期间为学习器提供额外信息**。



这段话描述的是 **MTL 中"使用未来预测现在"** 的核心思想：

**核心概念：**
- 有些特征对预测很有帮助，但在需要做预测时还不可用（如需要时间才能获得的实验室测试结果）
- 训练时：可以先收集这些特征，作为**额外的 MTL 任务**来训练模型
- 运行时：忽略这些额外任务的输出，因为此时特征还不可用

**作用：**
这些额外任务的主要功能是**在训练期间提供额外信息**，帮助模型学习更好的内部表示，从而提升主任务的性能。

**典型例子：**
医院预测患者病情，某些检查结果需要几天才能出来，但可以先用这些检查结果训练模型，运行时只用主任务预测。



#### Q2

**未来的测量在许多离线学习问题中都是可用的**。一个非常不同的例子是，机器人或自动驾驶车辆如果经过物体附近，可以更准确地测量物体的大小、位置和身份。例如，当车辆经过道路条纹时可以可靠地检测到它们，但在车辆前方远处检测它们超出了当前的技术水平。由于驾驶将未来的道路带到汽车附近，条纹可以在经过时准确测量并添加到训练集中。它们不能用作输入，因为在自主驾驶时它们将无法及时可用。然而，作为 MTL 输出，它们提供了额外信息，有助于学习，而无需在运行时可用。



这段话通过自动驾驶的具体例子，详细解释了"使用未来预测现在"的概念：

**场景分析：**

| 时间点           | 道路条纹位置 | 能否检测       | 是否可用作输入 |
| ---------------- | ------------ | -------------- | -------------- |
| 当前时刻（远处） | 远在车前方   | ❌ 超出技术水平 | ❌ 不可用       |
| 经过时（近处）   | 车辆正上方   | ✅ 可靠检测     | ✅ 可用         |
| 未来时刻（已过） | 车后方       | ✅              | ✅              |

**关键思想：**

1. **训练时：** 车辆经过条纹时，可以准确测量其大小、位置、身份 → 作为额外的 MTL 输出任务训练模型

2. **运行时：** 条纹还在车前方远处，无法及时检测 → 这些额外任务的输出在运行时无法获得

3. **核心价值：** 虽然运行时用不到这些输出，但**训练时**它们提供了额外信息，帮助模型**学习更好的特征表示**（如学习识别条纹的视觉特征）

**本质：**这是一种**间接监督** —— **用未来才能获得的信息来辅助当前的学习**，提升主任务（如车道保持）的性能，而**无需在运行时依赖**这些信息。



#### Q3：

有时在 单个误差度量 或 单个输出表示 中捕获所有重要内容是很困难的。当替代度量或输出表示捕获问题的不同但有用的方面时，可以使用 MTL 来从中受益。

这段话描述的是 **MTL 的另一个重要应用场景**：

**核心思想：**

有些问题很难用单一的误差度量或单一的输出表示来完全捕获其所有重要内容。但可能存在**多个替代的度量或输出表示**，每个都能捕获问题的不同但有用的方面。

**MTL 的作用：**
- 让模型同时学习多个不同的度量/表示
- 每个任务提供不同角度的信息
- 综合这些信息，模型可以学到更全面、更鲁棒的特征

**具体例子：**

假设要训练一个图像分类模型识别"汽车"：

| 任务      | 捕获的方面 | 输出表示 |
| --------- | ---------- | -------- |
| 主任务    | 汽车品牌   | 类别标签 |
| 额外任务1 | 汽车颜色   | 颜色标签 |
| 额外任务2 | 汽车位置   | 边界框   |
| 额外任务3 | 汽车部件   | 语义分割 |

每个任务都捕获了"汽车"的不同方面：
- 品牌 → 车标、整体造型
- 颜色 → 外观特征
- 位置 → 空间信息
- 部件 → 结构信息

**本质：**
MTL 通过同时学习多个相关任务，让模型从**多个角度**理解问题，从而获得更全面的特征表示，提升主任务的性能。



#### Q：4.6 顺序迁移具体实现方法

核心流程

```
阶段1：先前学习
┌─────────────────────────────────────┐
│  任务 A 的训练数据 + 模型 M_old      │
│  训练得到 M_old                      │
└─────────────────────────────────────┘
                    ↓
阶段2：数据不可用（但模型可用）
┌─────────────────────────────────────┐
│  任务 A 的训练数据已丢失/删除        │
│  但 M_old 仍然存在                   │
└─────────────────────────────────────┘
                    ↓
阶段3：合成数据 + MTL
┌─────────────────────────────────────┐
│  用 M_old 对输入 x 进行预测          │
│  得到合成标签 y' = M_old(x)          │
│  将 (x, y') 作为额外 MTL 任务        │
└─────────────────────────────────────┘
                    ↓
阶段4：训练新模型
┌─────────────────────────────────────┐
│  主任务：任务 B 的真实标签            │
│  额外任务：M_old 的预测（合成数据）   │
│  同时学习两个任务                    │
└─────────────────────────────────────┘
```

具体例子

假设：
- 先前任务：图像分类（猫/狗）→ 模型 M_old
- 当前任务：图像分类（汽车/自行车）
- M_old 的训练数据已丢失

**合成数据生成：**

1. 收集新的图像数据（汽车/自行车）
2. 用 M_old 对这些图像进行预测（预测是猫还是狗）
3. 将 M_old 的预测作为额外任务的标签

**训练过程：**
```
输入图像 x
    ↓
┌──────────────────────────────────────┐
│  共享特征提取器                       │
└──────────────────────────────────────┘
    ↓           ↓
┌────────┐  ┌────────┐
│ 主任务  │  │ 额外任务│
│ 汽车/   │  │ M_old  │
│ 自行车  │  │ 预测   │
└────────┘  └────────┘
```

采样策略

**问题：** 用什么分布来采样输入 x 生成合成数据？

**方法1：使用当前任务的分布**
- 用任务 B 的训练数据作为输入
- 通过 M_old 生成预测
- 简单，但可能无法充分探索 M_old 的知识

**方法2：在更多点上采样**

- 如果 M_old 很复杂，但任务 B 数据很少
- 可以额外采样一些输入点，更好地表示 M_old
- 更准确，但计算成本更高

优势

1. **避免灾难性干扰：** 不会忘记旧任务（因为不直接训练旧任务）
2. **不需要原始数据：** 只需要模型，不需要原始训练数据
3. **灵活：** 可以适应当前任务的数据分布



#### Q：用一个预测猫狗的模型，迁移到预测自行车和汽车的模型上，合适么？

分析：猫狗 → 汽车/自行车迁移的合适性

可能有效的原因

| 层级 | 可迁移的特征     | 说明                     |
| ---- | ---------------- | ------------------------ |
| 低级 | 边缘、纹理、颜色 | 所有视觉任务共用         |
| 中级 | 轮子、窗户、形状 | 部分重叠（自行车有轮子） |
| 高级 | 猫眼、狗耳       | 对车辆任务无帮助         |

可能无效的原因

1. **语义域差距大：** 动物 vs 车辆，特征差异显著
2. **高阶特征不通用：** 猫狗模型学到的"毛茸茸""耳朵形状"对车辆无用
3. **可能产生负迁移：** 强制学习不相关特征反而损害性能

论文的核心观点

论文强调的是：**即使先前模型较差，MTL 仍可能有帮助**，因为：
- 合成数据提供了额外的训练信号
- 模型可以**自动学习哪些特征是有用的**
- 通过任务权重调整，可以**减少不相关任务的影响**

实际应用中的例子

| 迁移场景            | 合适性 | 原因                       |
| ------------------- | ------ | -------------------------- |
| ImageNet → 医学图像 | ✅      | 低级特征通用               |
| 猫狗 → 狮子老虎     | ✅      | 同域，特征高度重叠         |
| 猫狗 → 汽车自行车   | ⚠️      | 低级特征有用，高级特征无用 |
| 文本分类 → 图像分类 | ❌      | 完全不同模态               |

**结论：** 这个迁移场景**可能部分有效**，但效果有限。论文的要点是 MTL 可以**自动调整**对额外任务的依赖程度，避免过度迁移。



#### Q：顺序迁移 vs 知识蒸馏

相似之处

| 特征                   | 顺序迁移   | 知识蒸馏             |
| ---------------------- | ---------- | -------------------- |
| 都使用预训练模型       | ✅ 教师模型 | ✅ 教师模型           |
| 都是模型指导新模型学习 | ✅          | ✅                    |
| 都利用教师模型的输出   | ✅ 合成标签 | ✅ 软标签（概率分布） |

关键区别

| 方面                   | 顺序迁移（本文）            | 知识蒸馏                        |
| ---------------------- | --------------------------- | ------------------------------- |
| **教师模型的使用方式** | 生成合成数据标签            | 提供软标签概率分布              |
| **学生模型的训练目标** | 最小化与合成标签的差距      | 最小化与软标签的KL散度          |
| **是否保留教师模型**   | ❌ 只用其预测                | ✅ 通常保留用于推理              |
| **任务关系**           | 可以是不同任务（猫狗→汽车） | 通常是相同任务（大模型→小模型） |
| **目的**               | 利用旧任务的信息辅助新任务  | 压缩模型，保留知识              |

具体对比

**顺序迁移：**
```
教师模型 M_old → 生成硬标签 y' = argmax(M_old(x))
                        ↓
                学生模型学习：L = CrossEntropy(y', student(x))
```

**知识蒸馏：**
```
教师模型 T → 输出软标签 p = softmax(T(x)/τ)
                        ↓
                学生模型学习：L = KL(p, student(x))
```

本质区别

- **顺序迁移：** 任务可能不同，利用旧任务的**知识**
- **知识蒸馏：** 任务相同，压缩模型的**能力**

**结论：** 两者有相似之处，但顺序迁移更侧重于**跨任务知识迁移**，而知识蒸馏更侧重于**模型压缩**。



#### Q：解释下文

许多 MTL 有用的领域是某些特征用作输入不切实际的领域。MTL 提供了一种从这些特征中受益的方法（而不仅仅是忽略它们），将它们用作额外任务。是否可能某些特征作为输出比作为输入更有用？令人惊讶的是，是的。可以构造一些问题，其中某些特征作为输出比作为输入更有用。

核心思想

这段话描述了一个**违反直觉但重要的概念**：**某些特征作为输出比作为输入更有用**。

具体例子

**场景：** 预测汽车是否会出故障

| 特征                  | 作为输入       | 作为输出       |
| --------------------- | -------------- | -------------- |
| **发动机温度**        | ✅ 可获取       | ✅ 可预测       |
| **驾驶员年龄**        | ✅ 可获取       | ✅ 可预测       |
| **3个月后的维修记录** | ❌ 运行时不可用 | ✅ 训练时可获取 |

为什么作为输出更有用？

**例子1：发动机温度**
- 作为输入：直接使用温度值预测故障
- 作为输出：让模型**学习预测发动机温度**，迫使模型学习发动机工作的内部机制
- 结果：模型学到更好的特征表示，提升故障预测性能

**例子2：3个月后的维修记录**
- 作为输入：运行时不可用（需要等3个月）
- 作为输出：训练时可用，作为额外任务
- 结果：帮助模型理解"什么样的特征组合会导致未来故障"

本质

**作为输出的价值：**
- 不是为了得到输出本身
- 而是**迫使模型学习更好的内部表示**
- 额外任务提供**间接监督信号**，帮助模型理解数据的深层结构

**结论：** 作为输出的特征可以充当**"辅助老师"**，帮助模型学习更有意义的特征，即使我们并不真正需要这些输出。



#### Q：7.1 多任务预测

MTL 在一个学习器上并行训练许多任务，但这并**不意味着应该使用一个学习到的模型对多个任务进行预测**。在单个学习器上训练多个任务的原因是一个任务可以从其他任务的训练信号中包含的信息中受益，而不是减少必须学习的模型数量。在所有任务的中等性能和任何单个任务的最佳性能之间可以进行权衡的地方，通常最好一次优化一个任务的性能，并允许额外任务的性能下降。MTL KNN/LCWA 和 MTL TDIDT 中的任务权重使这种权衡显式化；学习器甚至可以忽略一些任务以在主任务上实现更好的性能。

需要多个任务预测的地方（如 CAP，第 4.7 节），为每个所需任务训练单独的 MTL 模型可能很重要。然而，对于反向传播 MTL，使用平等对待所有任务并在共享隐藏层中具有足够容量以允许隐藏层的某些部分专门用于单个任务的架构，通常可以在一次训练运行中学习所有任务的模型。如果使用早停，重要的是对每个任务单独应用它；并非所有任务都以相同的速率训练或过拟合。最简单的方法是在每个任务性能最佳时拍摄网络快照，而不是试图在其他任务仍在训练时停止某些任务的训练。如果某些任务比其他任务训练得快得多，降低已经达到最佳性能的任务的学习率是防止它们过拟合以至于拖累其他较慢任务过拟合的一种方法。

多任务预测详解

核心误区

**常见误解：** MTL 在一个学习器上训练多个任务 → 用一个模型同时预测所有任务

**正确理解：** MTL 的目的是让任务**相互受益**，而不是**减少模型数量**

任务权重的权衡

```
场景：三个任务同时学习
┌─────────────────────────────────────┐
│  任务A（主任务）：权重 1.0           │
│  任务B（额外任务）：权重 0.5         │
│  任务C（额外任务）：权重 0.3         │
└─────────────────────────────────────┘

权衡结果：
任务A性能：★★★★★ (95%)
任务B性能：★★★☆☆ (70%)
任务C性能：★★☆☆☆ (60%)

如果单独训练：
任务A性能：★★★★☆ (85%)
任务B性能：★★★★☆ (80%)
任务C性能：★★★★☆ (75%)
```

**关键洞察：** MTL 可能牺牲额外任务的性能来提升主任务

何时需要多个模型？

| 场景                   | 策略                                | 原因                   |
| ---------------------- | ----------------------------------- | ---------------------- |
| 需要所有任务的最优性能 | 为每个任务训练单独的 MTL 模型       | 避免任务间相互干扰     |
| 主任务最重要           | 一个 MTL 模型，允许额外任务性能下降 | 利用额外任务提升主任务 |
| 任务高度相关           | 一个 MTL 模型，共享大部分参数       | 最大化任务间协同       |

反向传播 MTL 的架构

```
输入 x
    ↓
┌─────────────────────────┐
│   共享隐藏层（大容量）    │
│   ┌─────────────────┐   │
│   │ 任务A专用区域    │   │
│   │ 任务B专用区域    │   │
│   │ 任务C专用区域    │   │
│   │ 共享区域        │   │
│   └─────────────────┘   │
└─────────────────────────┘
    ↓           ↓           ↓
┌────────┐ ┌────────┐ ┌────────┐
│ 任务A  │ │ 任务B  │ │ 任务C  │
│ 输出层 │ │ 输出层 │ │ 输出层 │
└────────┘ └────────┘ └────────┘
```

**设计要点：**
- 共享层容量足够大
- 允许某些部分专门用于单个任务
- 自动学习哪些特征应该共享

早停策略

**问题：** 不同任务以不同速率训练和过拟合

**错误做法：**
```
任务A：████████████████████  (过拟合)
任务B：████████████░░░░░░░░  (欠拟合)
任务C：████████████████████  (过拟合)
       ↑
       同时停止 → 某些任务过拟合，某些欠拟合
```

**正确做法：**

```
任务A：在第7轮拍摄快照 → 最佳性能
任务B：在第9轮拍摄快照 → 最佳性能
任务C：在第11轮拍摄快照 → 最佳性能

每个任务独立选择最佳停止点
```

防止过拟合的策略

**问题：** 学得快的任务过拟合 → 拖累其他任务

**解决方案：**
1. 监控每个任务的验证误差
2. 当某任务达到最佳性能时，降低其学习率
3. 让其他任务继续学习
4. 在每个任务的最佳点拍摄快照

```
任务A：学习率 0.01 → 0.001 (在第7轮降低)
任务B：学习率 0.01 → 0.01  (保持)
任务C：学习率 0.01 → 0.01  (保持)
```

关键总结

| 要点       | 说明                             |
| ---------- | -------------------------------- |
| MTL 目的   | 让任务相互受益，不是减少模型数量 |
| 架构设计   | 共享层大容量，允许任务专用区域   |
| 早停策略   | 每个任务独立选择最佳停止点       |
| 学习率调整 | 学得快的任务降低学习率           |
| 性能权衡   | 主任务优先，允许额外任务性能下降 |

**结论：** MTL 的核心是**智能共享**，不是**强制共享**。需要根据任务关系和需求灵活设计架构和训练策略。



#### Q：7.2 反向传播 MTL 中的学习率

通常在所有任务以相似速率学习并在大约相同时间达到最佳性能时，反向传播 MTL 中可以获得更好的性能。如果主任务在额外任务之前训练很长时间，它就无法从额外任务尚未学到的东西中受益。如果主任务在额外任务之后训练很长时间，它就无法塑造额外任务学到的东西。此外，如果额外任务开始过拟合，由于隐藏层表示的重叠，它们可能会导致主任务也过拟合。

控制不同任务学习速率的最简单方法是调整每个输出任务的学习率。一种方法是使用所有任务相等的学习率训练网络，然后第二次训练，降低学习最快任务的学习率。这个过程的几次迭代通常足以使大多数任务在大约相同时间达到峰值性能。然后使用每个任务的早停来选择每个任务的最佳停止点。我们目前正在测试一种自动化这种学习率调整的算法。它不是在训练期间对每个任务使用恒定的学习率，而是根据该任务的进展在训练期间自适应地调整每个任务的学习率。提前计划的任务学习率降低，直到较慢的任务赶上。此方法仍然需要至少一次先前的训练运行来估计每个任务在开始过拟合之前会达到多远。



核心问题：任务学习速率不匹配

```
时间线：
任务A：████████████████████  (学习快)
任务B：██████░░░░░░░░░░░░░░  (学习慢)
       ↑                    ↑
    任务B开始时            任务A已过拟合
    任务A已过拟合          任务B才开始
```

**问题：**
- 任务A学得太快 → 在任务B还没学到东西时就已经过拟合
- 任务B学得太慢 → 无法帮助任务A

解决方案：调整学习率

**方法1：手动调整**

| 步骤 | 操作                     | 目的                     |
| ---- | ------------------------ | ------------------------ |
| 1    | 用相同学习率训练         | 基线                     |
| 2    | 降低学习最快任务的学习率 | 让它慢下来               |
| 3    | 迭代几次                 | 使任务同步               |
| 4    | 使用早停                 | 选择每个任务的最佳停止点 |

**方法2：自适应调整（更先进）**

```
训练过程中：
┌─────────────────────────────────────┐
│  监控每个任务的进展                   │
│  ↓                                   │
│  任务A学得快 → 降低其学习率           │
│  任务B学得慢 → 保持/提高其学习率      │
│  ↓                                   │
│  直到所有任务同步                     │
└─────────────────────────────────────┘
```

具体例子

**场景：** 三个任务同时学习

| 任务      | 初始学习率 | 调整后学习率 | 达到峰值时间 |
| --------- | ---------- | ------------ | ------------ |
| 主任务    | 0.01       | 0.01         | 100 epochs   |
| 额外任务1 | 0.01       | 0.005        | 100 epochs   |
| 额外任务2 | 0.01       | 0.003        | 100 epochs   |

**调整过程：**
```
第1轮：任务1学得最快 → 降低其学习率
第2轮：任务2学得最快 → 降低其学习率
第3轮：三个任务速率接近 → 保持
```

### 早停策略

**问题：** 每个任务的最佳停止点不同

**解决方案：**
- 为每个任务维护独立的验证集
- 监控每个任务的验证误差
- 当某个任务的验证误差开始上升时，停止该任务的训练

```
任务A：验证误差 ↓↓↓↓↓↓↑↑↑  → 在第7轮停止
任务B：验证误差 ↓↓↓↓↓↓↓↓↓↑  → 在第9轮停止
任务C：验证误差 ↓↓↓↓↓↓↓↓↓↓↓↑ → 在第11轮停止
```

### 关键洞察

| 要点       | 说明                             |
| ---------- | -------------------------------- |
| 同步学习   | 所有任务应在大约相同时间达到峰值 |
| 避免过拟合 | 一个任务过拟合会影响其他任务     |
| 自适应调整 | 根据任务进展动态调整学习率       |
| 早停       | 每个任务独立选择最佳停止点       |

**结论：** MTL 的成功不仅取决于共享什么，还取决于何时共享。任务学习速率的同步是 MTL 性能的关键因素。



#### Q：7.3 并行转移与串行转移

MTL 是并行转移。串行转移（Pratt & Mostow 1991; Pratt 1992; Sharkey & Sharkey 1992; Thrun & Mitchell 1994; Thrun 1995）似乎更容易，情况可能并非如此。并行转移的优点是：

- 所有任务正在学习的所有细节对所有任务都可用，因为所有任务都在同时学习。
- 在许多应用中，额外任务可以及时获得以便与主任务并行学习。并行转移不需要定义训练序列——任务训练的顺序在串行转移中通常会产生影响。
- 任务通常相互受益，这是线性序列无法捕捉的。例如，如果任务 1 在任务 2 之前学习，任务 2 就不能帮助任务 1。这不仅降低了任务 1 的性能，还可能降低任务 1 帮助任务 2 的能力。

当任务自然地串行出现时，使用并行转移进行串行转移是很简单的。如果可以存储训练数据，使用任何已可用的任务执行 MTL，在出现新任务时重新学习。如果无法存储训练数据，可以从先前学习的模型生成合成数据（参见第 4.6 节）。有趣的是，虽然使用并行转移进行串行转移很容易，但使用串行转移进行并行转移则不那么容易。请注意，可以将串行和并行转移结合起来；O'Sullivan 目前正在探索一个在卡内基梅隆大学结合 MTL 和 EBNN 用于机器人终身学习的论文。



核心对比

| 特性       | 并行转移（MTL）  | 串行转移     |
| ---------- | ---------------- | ------------ |
| 学习方式   | 所有任务同时学习 | 任务依次学习 |
| 任务间帮助 | ✅ 相互受益       | ❌ 单向帮助   |
| 训练顺序   | 无影响           | 有影响       |
| 灵活性     | 高               | 低           |

串行转移的问题

```
串行转移：
任务1 学习 → 任务2 学习 → 任务3 学习
    ↓            ↓            ↓
  任务1不能     任务2不能     任务3不能
  被任务2帮助   被任务3帮助   被其他帮助

并行转移：
任务1 ←→ 任务2 ←→ 任务3
    ↓        ↓        ↓
  所有任务相互帮助
```

具体例子

**场景：** 学习三个相关任务（猫狗分类、车辆分类、飞机分类）

**串行转移：**
1. 先学猫狗分类
2. 再学车辆分类 → 不能帮助猫狗分类
3. 最后学飞机分类 → 不能帮助前两个任务

**并行转移：**
1. 同时学习三个任务
2. 每个任务都从其他任务中受益
3. 整体性能更好

用并行转移模拟串行转移

**情况1：可以存储训练数据**
- 当新任务出现时，用所有可用数据重新训练
- 简单直接

**情况2：不能存储训练数据**
- 从先前模型生成合成数据（第4.6节）
- 间接实现串行到并行的转换

关键洞察

**并行转移可以轻松模拟串行转移，但反过来不行。**

**原因：**
- 并行转移：所有信息同时可用
- 串行转移：信息按顺序释放，无法回溯

**结论：** MTL（并行转移）更强大、更灵活，应该优先使用。



#### Q：7.5 架构

正则化方法（如权重衰减）可以与 MTL 一起使用。通过减少模型中有效自由参数的数量，正则化促进共享。然而，过强的共享偏置会损害性能。如果任务比它们的相似之处更不同（通常情况），重要的是**允许任务学习相当独立的模型，仅在存在共同隐藏结构的地方重叠**。这就是为什么当共享隐藏层的大小远小于在分别训练时为任务提供良好性能的 STL 隐藏层大小之和时，MTL 性能通常会下降的一个原因。

这是什么意思？

核心思想：共享与独立的平衡

关键权衡

| 偏向共享         | 偏向独立       |
| ---------------- | -------------- |
| 任务相似度高     | 任务差异大     |
| 共享层较大       | 共享层较小     |
| 所有任务性能均衡 | 主任务性能优先 |

问题所在

**过强的共享偏置：**
- 强制所有任务共享大量参数
- 忽略任务间的差异
- 导致某些任务性能下降

**过弱的共享偏置：**
- 每个任务独立学习
- 无法利用任务间的共性
- 浪费 MTL 的优势

最佳实践

**正确的 MTL 策略：**
```
输入 x
    ↓
┌─────────────────────────┐
│   共享层（较小）         │  ← 只捕获共同特征
└─────────────────────────┘
    ↓           ↓
┌────────┐  ┌────────┐
│ 任务A  │  │ 任务B  │  ← 任务特定层
│ 独立层 │  │ 独立层 │
└────────┘  └────────┘
```

**本质：**
- 共享层捕获**共同的底层特征**（如边缘、纹理）
- 任务特定层学习**独特的高层特征**（如猫眼 vs 车轮）

实际含义

| 情况       | 结果                                     |
| ---------- | ---------------------------------------- |
| 共享层太小 | MTL 性能下降（无法捕获足够的共性）       |
| 共享层太大 | 可能过度正则化（强制共享不该共享的内容） |
| 合适的大小 | 平衡共享与独立，获得最佳性能             |

**结论：** MTL 成功的关键不是"共享多少"，而是"共享什么"。需要让模型自动学习哪些特征应该共享，哪些应该独立。
