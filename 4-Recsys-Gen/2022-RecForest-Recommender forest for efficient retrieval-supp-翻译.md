## A 森林构建

### A.1 均衡 K-means

为保证检索效率，构建的树期望是一棵完全的 K 叉树。然而，item数量 N 不一定满足此要求。我们通过从自身插入 KH−N 个随机采样的item来扩充数据集，使其恰好包含 KH 个item，其中 H = ⌈log_K N⌉ 为树的高度。我们使用算法 1 中的均衡 K-means 进行层次化item集划分。具体而言，假设一个聚类包含 K
$$
\times
$$
m 个item，算法将其拆分为 K 个聚类，使每个聚类恰好包含 m 个item。在每次迭代中，我们首先按顺序为每个质心分配 m 个最近的未分配item，然后根据item分配更新质心。聚类算法在分配不再变化时终止。

**算法 1：均衡 K-means**
```
输入：item集 D，聚类数 K
输出：{D₁, D₂, ..., D_K}
1. m ← |D|/K
2. 随机初始化 K 个质心 C = {c₁, c₂, ..., c_K}
3. repeat
4.   U ← D
5.   for k = 1 → K do
6.     U_s ← 按与 c_k 的距离升序对 U 中的item排序
7.     D_k ← U_s[0:m−1]
8.     U ← U \ D_k
9.     c_k ← 1/m ∑_{x∈D_k} x
10. until 分配不再变化
```

### A.2 树的构建

如第 2.3.2 节所述，每棵树通过结合随机划分（Random）和均衡 K-means 构建，以保证多样性和语义接近度。对于随机策略，每个聚类中的item被随机划分为 K 个等大小的子集。当与均衡 K-means 结合时，对于包含 n 个item的聚类，首先随机选取 n mod K 个item，从中每个子聚类有放回地采样一个item，剩余item基于均衡 K-means 进行划分。此方法简称为 **Random+Kmeans**。通过递归应用 Random+Kmeans 策略直到每个聚类仅包含一个item，可以成功构建树索引。重复树构建过程可以生成多样化的树以形成森林。我们在算法 2 中总结了该过程。

**算法 2：树构建**
```
输入：数据集 D，分支数 K，随机比例 δ
输出：构建的树
1. Q ← 包含元素 D 的队列
2. while Q 不为空 do
3.   D_top ← pop(Q)
4.   n ← |D_top|
5.   D0 ← 从 D_top 中不放回地随机抽取 n mod K 个item
6.   D_top ← D_top \ D0
7.   {D₁, D₂, ..., D_K} ← Balanced-Kmeans(D_top, K)
8.   for k = 1 → K do
9.     i ← 从 D0 中有放回地采样一个item
10.    push(Q, {i} ∪ D_k)
```

## C 训练和推理的伪代码

在我们的 RecForest 中，所有树共享编码器，但每棵树有唯一的解码器。训练框架总结在算法 3 中。注意我们仅给出一个训练实例以便清晰说明，实际实现中可以批量方式进行。此外，推理框架总结在算法 4 中。一旦收集了每棵树生成的候选，我们计算候选在每棵树上的生成概率以进行排序。

**算法 3：RecForest 训练**
```
输入：森林 = {tree₁, tree₂, ..., tree_T}，训练实例 (x_u, i_t)，每棵树对应的编码器和解码器 (1 ≤ t ≤ T)
1. z_u ← Encoder(x_u)
2. for each t ∈ {1, 2, ..., T} do
3.   target ← 获取item i 在树 t 上的路径
4.   decoder-input ← ['start', target[0:H-1]]  // H 为树高度
5.   prediction ← Decoder_t(z_u, decoder-input)
6.   L(u, i) ← loss(prediction, target[1:H]) 根据公式 (1)
7.   从 L(u, i) 反向传播
8.   通过梯度下降更新 Encoder 和 Decoder_t
```

**算法 4：RecForest 推理**
```
输入：森林 = {tree₁, ..., tree_T}，每棵树对应的编码器和解码器 Decoder_t，
      用户特征 x_u，束大小 B，返回item数 n
输出：用户 u 的 top-n item
1. R ← {}
2. z_u ← Encoder(x_u)
3. for t ∈ {1, 2, ..., T} do
4.   paths ← Beam-Search(Decoder_t, z_u, B)
5.   for each p ∈ paths do
6.     item i ← get-item(p, tree_t)
7.     R ← R ∪ {i}
8. for each item i ∈ R do
9.   score[i] = 0
10.  for t ∈ {1, 2, ..., T} do
11.    path ← get-path(i, tree_t)
12.    p_t(i) ← 基于 Decoder_t 计算路径概率
13.    score[i] = score[i] + log p_t(i)
14.  基于分数从 R 中选择 top-n item
```

## D 评估指标

**归一化折现累积增益（NDCG）** 用于衡量推荐引擎的性能。折现累积增益（DCG）计算如下：

DCG@k =
$$
\sum
$$
_{i=1}^{k} (2^{r_i} - 1) / $log_2$ (i+1)

其中 r_i 表示相关性分数，k 为返回item数。由于我们关注隐式反馈，如果测试用户真正与返回的第 i 个item交互则 r_i = 1，否则 r_i = 0。

NDCG@k = DCG@k / iDCG@k

其中 iDCG 表示理想 DCG，即根据相关性分数降序排列所有返回item，并在排序后的item上计算 DCG。此外，我们还关注检索索引的内存消耗和推理效率。具体地，我们记录检索系统的模型大小和推理时间消耗。

## E 序列推荐场景的实验细节

### E.1 序列推荐场景的基线

- **TDM [29] 及其变体 JTM [28]**：由阿里巴巴提出，是基于树的推荐框架，同时训练用户-item偏好模型和树结构。叶子节点代表item，内部节点代表相应叶子节点所属的聚类。在树上进行束搜索，从粗粒度聚类到细粒度聚类检索item。TDM 和 JTM 的主要区别在于item与叶子节点之间双射映射关系的更新方式。
- **深度兴趣网络（DIN）[26]**：利用深度模型从用户的序列交互中刻画用户对item的偏好。具体地，DIN 将训练任务视为反映用户是否与某item交互的二分类问题。由于 DIN 不能用于高效推荐，我们报告基于暴力搜索的性能。
- **Youtube DNN [1]**：由 Google 提出，从序列用户-item交互历史中学习用户表示和item表示的深度神经网络模型。然后使用用户表示与item表示之间的内积来捕获用户对对应item的偏好，将推荐任务转化为最大内积搜索（MIPS）。在我们的实验中，我们主要通过 MIPS 的暴力搜索来展示 Youtube DNN 的性能。
- **SCANN [5] 和 IPNSW [16]**：分别代表量化方法和图方法。为实现与我们的模型的公平比较，我们使用 Transformer 编码器建模用户交互，并用item嵌入替换解码器。适配后的模型以与 DIN 相同的方式训练，以获得用户表示和item表示，从而学习到的表示可用于构建 SCANN 索引和 IPNSW 索引。

TDM、JTM 和 DIN 的开源代码基于阿里巴巴的 X-DeepLearning 框架，我们使用 PyTorch 重新实现它们。Youtube DNN 的开源代码也可获取。

### E.2 序列推荐场景的详细设置

在每个数据集中，我们随机选择 10% 的用户作为验证用户，10% 作为测试用户，其余作为训练用户。遵循 TDM [29] 和 JTM [28] 的设置，我们使用滑动窗口将用户-item交互历史切割为长度最多为 70 的片段。每个窗口至少包含 15 个交互，如果窗口中的交互少于 70 个则应用零填充。在训练阶段，每个窗口中前 69 个用户-item交互作为上下文，第 70 个item作为真实标签。对于验证用户和测试用户，后半部分交互作为真实标签，前半部分交互作为上下文。所有方法的隐藏大小设为 96。

DIN [26] 包含嵌入层后接大小为 [128, 64, 2] 的 MLP，输出喜欢/不喜欢概率，用作 TDM 和 JTM 的偏好模型。Youtube DNN [1] 包含嵌入层后接大小为 [128, 64, 96] 的 MLP，负采样数设为 1,000。对于 SCANN，我们遵循开源代码的默认设置，但使用 Python 和 PyTorch 实现以实现公平的效率比较。具体地，叶子数为 2,000；子空间数为 24，每个子空间的维度为 4；每个子空间中的码字数为 16；阈值设为 0.2。为构建 IPNSW 的图索引，每个节点的最大度设为 16，束大小设为 100。

对于我们的 RecForest、Youtube DNN、TDM、JTM 和 DIN，使用 Adam [9] 作为优化器，学习率设为 1.0e-3 并采用指数衰减。在推理中，RecForest、TDM、JTM 和 IPNSW 的束大小设为 100（除非另有指定）。对于 RecForest，分支数设为 18；在 Movie 和 MIND 上树数设为 2，在其他数据集上设为 4（除非另有指定）。用于构建 RecForest 森林的item表示通过在每个数据集上预训练 DIN 模型获得。

## F 非序列推荐场景的实验

在非序列场景中，我们仅使用用户 ID 表示用户，并使用特征编码器建模用户表示。具体地，用户 ID 的可学习嵌入向量表示用户表示。

### F.1 基线

经典深度模型神经协同过滤（NCF）[6] 在给定用户 ID 和item ID 的情况下刻画用户对item的偏好。由于与任何先进的用户-item（或用户-节点）偏好模型的兼容性，我们在 TDM [29] 和 JTM [28] 框架中使用 NCF 进行偏好建模。对于 Youtube DNN，我们用用户 ID 的嵌入向量替换序列推荐场景中使用的用户表示学习部分。通过这种方式，Youtube DNN 可以兼容非序列推荐任务。SCANN 和 IPNSW 基于 Youtube DNN 学习到的表示构建。注意，基于暴力搜索的 Youtube DNN 和 NCF 在在线服务中耗时过长，但可以视为两个强基线。

### F.2 实验设置

在每个数据集中，我们随机选择 10% 的用户作为验证用户，10% 作为测试用户，其余作为训练用户。对于验证用户和测试用户，我们随机选择四分之一的交互item作为真实标签，其余放入训练集。使用融合 NCF [6]，包含 GMF 和 MLP，每层神经元数设为 [512, 256, 128, 96]。其他必要设置如 E.2 节所述。
